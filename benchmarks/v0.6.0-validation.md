# v0.6.0 validation notes

The baseline is public v0.5.0 commit `be7afa23304386fa69e30b5dbb9f03a414ecd86f`. Runtime tests use temporary projects; no other project's state or global skill installation is changed by this release.

The entrypoint is 55.6% shorter by this measure. The combined Lead materials, conservatively including the entire new dispatch reference, are 46.6% shorter. References are read by role/need instead of all on every continuation. Current state and project-specific tasks are additional context and are not included in these counts.

These measurements do **not** establish a real <= 10% coordination token ratio or credit savings. Actual purpose-attributed usage is unavailable for a completed live TAO comparison; the numeric target remains unmeasured and public savings remain **Benchmark pending**.

## Local acceptance

`python -m unittest discover -s tests` passed all 70 tests on the release working tree. Skill quick validation passed. All eight Python source/test files parse with Python 3.9 grammar, and `git diff --check` passed. The suite retains the 34 state-machine tests and four forward scenarios; older repeated-word documentation assertions were consolidated into nine packaging/contract checks, with 14 relay tests and nine benchmark tests.

## Verification boundaries

- Runtime/state tests cover scope, ownership, dependency, completion/reopen, archive and recovery behavior. Read-only queries report pending updates without repairing; explicit recovery retains overwrite protection.
- Relay tests run a synthetic two-assignment workflow on one bound Worker, with revision guards, duplicate/uncertain delivery, missing/mismatched native proof, same-directory checks, no model overrides, and callbacks to the Lead.
- Benchmark tests cover the 10% boundary, excess, zero denominator, incomplete/missing attribution, synthetic records and old schema-v2 compatibility.
- CLI tests execute the explicit interpreter from an unrelated working directory with spaces/Chinese characters in the project path; bad arguments fail, help works, and a missing interpreter cannot count as a state operation.
- The helper has no editor-launch implementation. Skill instructions and invocation examples now distinguish terminal execution from viewing files. The original unexpected VS Code action has not been reproduced from its historical host trace; actual desktop GUI behavior and independent live Agent behavior are not established by these unit tests.
- Evals A-Z include realistic relay, missing-attestation, duplicate-send, terminal/help/editor and measurement scenarios. They are evaluation definitions, not claimed live Agent run results.
- Current desktop task tools do not expose the required actual/effective route proof. No substantive auto-created Worker or live cross-task message was used for release testing. Automatic new-task creation remains gated; existing Owner-created tasks can use the documented authorized relay path when tools are available.

CI runs the standard-library suite on Windows/Ubuntu and Python 3.9/3.13. Release acceptance requires all four jobs on the release commit; use the repository's commit-linked Actions results for the actual published run. Skill-format validation and Python 3.9 grammar checks are also required locally.
